{% comment %} Flash messages, on the design system. This used to be five near-identical blocks, each hardcoding a light-only palette (`text-green-800 bg-green-100 border-green-300` and so on). The design system already has theme-aware `.alert-success` / `-error` / `-warning` / `-info` / `-neutral`, so the colours now come from tokens and follow the theme instead of staying light in dark mode. Branches on `message.level_tag`, NOT `message.tags`. Django builds `tags` as `" "`, so `messages.success(request, "x", extra_tags="toast")` yields `"toast success"` — and an equality test against `"success"` misses it, dropping the message to the neutral style with the wrong icon. `level_tag` is the level on its own, so it matches exactly rather than by substring. The `.alert` class is kept deliberately: the timer at the bottom of this file selects `.alert` to dismiss these after ten seconds, and these ARE flash messages, so that is correct here. Anything that is a standing condition rather than a flash must NOT carry the class, or it disappears mid-sentence. {% endcomment %} {% if messages %}

{% comment %} Included at the top of allauth's account/email.html. Kept as a separate file so the vendor template gains exactly one line — see PROVENANCE.md. Why this page needs it at all: when an address hard-bounces we stop sending to it, and the only channel we would normally use to say so is email — to the address we just stopped using. Without this, a customer whose mailbox filled up or whose domain expired just goes silent and never learns why. Wording: what happened, what it means, what to do. It does not blame the person, because the usual causes are a full mailbox, an expired domain, or a receiving server that decided to reject us — and the last one is our fault, not theirs. It names password resets explicitly, since that is the consequence most likely to strand somebody. Uses `alert-error` for colour but **NOT the `alert` class**. `templates/components/messages.html` runs `document.querySelectorAll('.alert')` on a 10-second timer and removes every match anywhere on the page — a boilerplate bug (loose end 9). This is a standing condition, not a flash message, and must not vanish mid-sentence. A test pins the class out. The layout utilities are spelled out because `.alert` supplied them. Every class here already exists in the compiled `styles.css`. Do NOT reach for arbitrary-opacity utilities like `bg-error/10`: the first version of this file did, and they rendered as a transparent background with a grey border, because Tailwind only compiles classes it saw at build time.

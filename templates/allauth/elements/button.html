{% load allauth %} {% comment %} djlint:off allauth's button element, mapped onto the design system. Two bugs this replaces. It used `bg-blue-600 text-white`, which is not the design system's primary in either theme — so every allauth button was a different colour from every other button in the product. And the `href` branch emitted no class at all, so allauth's link-buttons ("Cancel", "Back") rendered as bare unstyled links. It also ignored `tags`, which allauth already passes — `secondary`, `link,cancel`, `outline`, `danger`. Every button therefore looked equally primary, including the ones meant to be quiet. Mapping them is what makes a Cancel next to a Confirm read correctly. It also forwards `form`, `id` and `value`, which upstream allauth forwards and this override used to drop. That was a functional break, not a cosmetic one: passkey and WebAuthn buttons are found by id, OIDC consent distinguishes grant from cancel by value, and logout-from-stage submits via `form=`. Variants come from static/mainapp/input.css: btn-contained | btn-outlined | btn-text, crossed with btn-primary | btn-secondary | btn-error. {% endcomment %} {% comment %} Precedence matters. allauth emits "outline,cancel" for confirmation-cancel and MFA-trust-cancel, so testing `cancel` before `outline` turned an explicitly requested outlined button into a flat text one.

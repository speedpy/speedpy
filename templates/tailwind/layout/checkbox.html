{% load crispy_forms_field %} {% comment %} A checkbox is the one field whose label sits to the RIGHT of the input, so it gets its own row and cannot reuse field.html's label-above layout. That is also how it lost its help text and its errors for a long time: this template rendered the input and the label and stopped. The input still carried `aria-describedby="_helptext"` pointing at an element that was never emitted, so a screen reader announced a description that did not exist, and — worse — a checkbox whose help text is a privacy disclosure showed the visitor nothing at all. Errors vanished the same way, which makes a failed required checkbox look like a form that simply refuses to submit. The help text and errors go BELOW the row, not beside the label: beside it they push the label away from its own checkbox and the pairing stops being readable. {% endcomment %}
